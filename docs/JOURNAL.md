# Журнал выводов

## 2026-11-26 — адаптация для iPhone Duo

Внешний дисплей, внутренний дисплей и окно Split View дают приложению разную доступную ширину и высоту. `AuthViewport` и `PinKeypad` используют ограничения окна после системных отступов. `DocumentsScreen` меняет количество колонок по ширине области списка. [Характеристики дисплеев Apple](https://www.apple.com/iphone-duo/specs/).

Виджет-тест с подменой системного ответа изменил размер окна во время ожидания OAuth и посреди набора PIN. В обеих проверках вход удалось завершить. Тест документов проверил переход между колонками, открытый документ после смены размера и доступность кнопки над системным отступом. Размеры кадров сверены со спецификацией снимков Apple, где внутренний дисплей описан размерами рендера. [Размеры снимков](https://developer.apple.com/help/app-store-connect/reference/screenshot-specifications/).

В `Info.plist` опубликованного приложения проверили `DTSDKName`. Apple описывает режим совместимости для сборок с SDK 26 и полноэкранный режим с SDK 27.1. GitHub-раннер имеет Xcode 26.6, а прямая ссылка на пакет Xcode 27.1 перенаправляет к авторизации Apple Developer. [Требования Apple](https://developer.apple.com/iphone-duo/prepare/) · [Образ GitHub Actions](https://github.com/actions/runner-images/blob/main/images/macos/macos-26-arm64-Readme.md).

## 2026-11-26 — Keychain в сборке симулятора

Сообщение об ошибке после входа относится к коду обработки уже принятого callback. Оно объединяло ошибки запроса токена и записи в защищённое хранилище.

Проверка опубликованного `Runner.app` показала отсутствие подписи пакета и прав Keychain. Проверены подпись и секции обеих архитектур. Тест Flutter воспроизвёл ошибку Keychain в момент сохранения после успешного ответа и проверил отдельное сообщение и доступность повторной попытки.

Первый запуск CI собрал и проверил подпись нового приложения. Чтение поля `keychain-access-groups` напрямую из подписи остановило сборку до запуска симулятора. Проверку подписи оставили, а права проверяются нативной операцией Keychain.

В скачанном архиве Xcode записал группу Keychain в секцию `__entitlements` исполняемого файла симулятора для `x86_64` и `arm64`. Список прав в записи подписи пуст. Это объясняет результат первой проверки CI.

На следующем запуске нативный тест успешно выполнил `SecItemAdd` и `SecItemCopyMatching` в процессе приложения. Проверка подтверждает доступ симулятора к Keychain. По исходному сообщению можно установить только этап сбоя. [Журнал теста](https://github.com/code-agent-43824/astralkeytest/actions/runs/45840026273/job/139978928588).

## 2026-11-26 — проверка demo OAuth

Адреса авторизации и токена в метаданных совпали с используемыми приложением. Запрос для текущего клиента с PKCE S256 и без браузерной сессии вернул `login_required` по зарегистрированной схеме приложения с исходным `state`. Это подтверждает принятие запроса и адреса возврата. Выдача живого токена требует прохождения CAPTCHA.

Сервер указывает `https://identity.astral.ru` как issuer и отвечает абсолютным HTTP-редиректом на форму того же demo-домена. На ответе есть HSTS, в Chromium форма открылась по HTTPS. Настройки issuer и схемы редиректа стоит сверить на стенде.

## 2026-11-26 — переход на экран входа

До исправления тесты на Android, iOS и Windows воспроизводили ошибку изменения `Overlay` во время построения экрана. После переноса навигации из `initState` в обработчик после первого кадра тесты проходят: Windows открывает форму токена, Android и iOS вызывают браузер. Внешний вход и платформенные вызовы подменены.

## 2026-10-31 — Windows-сборка и новый MSVC

Гипотеза: `local_auth_windows` версии 1.0.11 включает экспериментальные корутины через `/await`, которые MSVC 14.51 блокирует без явного разрешения устаревшего заголовка.

Проверка: в журнале GitHub Actions ошибка `STL1011` исходила из цели `local_auth_windows_plugin`. После добавления определения компилятора только для этой цели Windows-сборка и загрузка артефакта прошли; Android и iOS тоже прошли.

Вывод: сбой был вызван несовместимостью старой версии плагина с обновлённым компилятором Windows runner. Настройка возвращает сборку, но в будущем потребуется обновить плагин до версии без экспериментальных корутин.

## 2026-10-31 — падение приветственного экрана

Гипотеза: тест остался от старой версии экрана, а фиксированная колонка не помещается по высоте.

Проверка: на размере теста Flutter сообщил о переполнении `RenderFlex` и не нашёл старый заголовок. После добавления прокрутки и проверки актуального экрана тест проходит на размере 320 × 568; анализатор чист, debug APK собирается.

Вывод: причина падения была в устаревших ожиданиях теста и отсутствии прокрутки у приветственного экрана.
